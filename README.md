# 撲克牌心臟病（C++ / Win32 API）

> 程式設計(二) 期末專題，第 12 組**共同協作**完成：詹正宇、李思樺、鍾予薰。

這是用 Win32 API 和 GDI 從零畫出來的「心臟病」反應遊戲，沒有用任何遊戲引擎或圖形函式庫。畫面中央會依序翻出洗好的牌，右邊會循環顯示 1~10、J、Q、K。牌面點數和右邊提示一樣的那一刻，要搶先按下按鍵。

## 模式

| 模式 | 操作 | 判定 |
|---|---|---|
| 單人計時賽 | 空白鍵 | 用 `GetTickCount64()` 記錄翻牌與按鍵的時間差，算出反應時間 |
| 雙人鍵盤競速 | 玩家 A 按 `A`、玩家 B 按 `L` | 先按對的人獲勝；牌面不吻合時亂按，直接判對手贏 |
| 對戰模式（DLL） | 由 `bot_dll` 自動遊玩 | DLL 「看」畫面決定要不要按空白鍵 |
| 多人連線 | — | 有規劃、選單已放上去，但還沒有實作 |

## 建置

Windows + Visual Studio 2022：

1. 主程式：建立「Windows 桌面應用程式」專案，加入 `main.cpp`。
2. DLL：建立「動態連結程式庫 (DLL)」專案，加入 `bot_dll/dllmain.cpp`（使用預設的 `pch.h`），輸出檔名設定為 `s1142018.dll`，再放到主程式 exe 旁邊。
3. 沒有 DLL 也能正常玩，只是沒有對戰模式。

## 設計上的取捨

**按鍵捕捉：從全域熱鍵改成視窗訊息**
一開始用 `RegisterHotKey` 攔截空白鍵，但這是系統全域的，視窗沒有焦點時也會觸發。雙人模式改在 `WM_KEYDOWN` 裡處理 A / L 鍵，處理完後 `return 0`，避免訊息繼續流到 `DefWindowProc`，造成重複觸發。

**中文輸入法吃掉按鍵**
系統在注音輸入法狀態下，按下的字母會先被輸入法攔截，程式收不到 A / L。解法是在視窗建立後呼叫 `ImmAssociateContext(hwnd, NULL)`，讓這個視窗跟輸入法脫鉤。

**同一張牌只能搶一次**
雙人同時按鍵時，用 `currentCardProcessed_` 旗標確保每張牌只判定一次。雙人模式的翻牌間隔也從 100~1000ms 放慢到 1500~2500ms，給玩家辨識與移動手指的時間。

**DLL 為什麼只看像素**
主程式只在每次翻牌後呼叫 DLL 匯出的 `check(HWND)`，不告訴它現在是哪張牌。DLL 必須像真人一樣看畫面：

1. `BitBlt` + `GetDIBits` 擷取視窗畫面。
2. 找出每一列、每一行最長的深色連續像素，定位牌框。
3. 在牌的中央區域找連通區塊（blob）。2~10 直接數花色有幾顆；只有一顆時，依大小判斷是 A，還是 J/Q/K 的大字。
4. J/Q/K 和右側提示字，用 GDI 即時畫出樣板字，再算正規化相關係數比對。第一次遇到時會自動試不同字型大小與粗細，校正出最吻合的樣板。
5. 最高分要超過 0.55，而且要比第二名高 0.10 以上才算可信，兩邊都可信又一致時才送出空白鍵。

主程式和 DLL 之間只有 `check(HWND)` 這一個函式介面，耦合很低。代價是 DLL 依賴畫面長相（黑色牌框、提示字在牌的右側），主程式的版面一改，辨識參數就要跟著調。
